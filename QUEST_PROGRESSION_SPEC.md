# Quest Progression System Spec

**Date:** 2026-03-31 (updated from 2026-03-28)
**For:** Claude Code handoff
**Status:** Ready to build

---

## Overview

Lock all quests behind a progression chain so players experience the Rites of Passage in a guided sequence. Two quests are always open: Fire (Quest 0) and Food Foresting. Everything else is locked until earned.

The visual language: locked quests are greyed out with a light green lock icon. Unlocked quests are full color. Fire and Food Foresting get background images to make them visually magnetic as the entry point.

---

## Progression Chain

```
ALWAYS OPEN
  Fire (Quest 0)
  Food Foresting (featured, repeatable)

FIRE COMPLETE --> unlocks current real-world season's Rites
  (e.g., if player completes Fire in March, Spring Rites unlock)

1 RITE COMPLETE in Season 1 --> unlocks NEXT season in rotation
  Spring --> Summer --> Fall --> Winter --> Spring (wraps)

1 RITE COMPLETE in each of 4 seasons --> unlocks:
  - All Seasonal Practices (the 18 depth quests)
  - Routine quests (Fasting, Love to Heal Your Body)
  - Anytime quests
  - Elemental quests

ALL 13 RITES COMPLETE (Fire + quests 1-12) --> unlocks:
  - All Epic Quests
```

### Season Rotation Logic

The first season unlocked after Fire is based on the current real-world date:

| Current month | First season unlocked |
|---|---|
| March, April, May | Spring |
| June, July, August | Summer |
| September, October, November | Fall |
| December, January, February | Winter |

After completing 1 Rite in the first season, the next season in clockwise order unlocks. The rotation always goes: Spring > Summer > Fall > Winter > Spring.

Example: Player joins in October, completes Fire. Fall Rites unlock. They complete Wild Foraging (Fall Rite). Winter Rites unlock. They complete Communication Patterns (Winter). Spring unlocks. They do Potion Brewing (Spring). Summer unlocks. They do Dreaming Spaces of Love (Summer). Now all 4 seasons have at least 1 Rite complete: Seasonal Practices, Epic Quests, and Fasting all unlock.

### What "Complete 1 Rite" Means

A Rite is complete when the player has at least 1 completion logged for any quest in that season's Rites of Passage group:

| Season | Rites (any 1 counts) |
|---|---|
| Spring | Quest 1 (Potion Brewing), Quest 2 (Saving Seeds), Quest 3 (Healing Wholes) |
| Summer | Quest 4 (Dreaming Spaces), Quest 5 (Rites of Love), Quest 6 (Healing Circles) |
| Fall | Quest 7 (Wild Foraging), Quest 8 (Medicine Journey), Quest 9 (Tree Talk) |
| Winter | Quest 10 (Communication Patterns), Quest 11 (Coordination Patterns), Quest 12 (Breathplay) |

## Progress Indicator: Season Ring

A small visual component shown in two places:

1. **Epic Quest section header** (gate indicator)
2. **Quest page sidebar or top bar** (overall progression)

```
[ Spring ● ] [ Summer ○ ] [ Fall ● ] [ Winter ○ ]
  2 of 4 seasons complete
```

- Filled circle (●) = at least 1 Rite completed in that season
- Empty circle (○) = no Rites completed yet
- When all 4 are filled: "All seasons complete. Epic Quests unlocked."

Implementation: a `SeasonProgressRing` component, 4 small dots or icons with season labels.

## Data Model Changes

### Option A: Local Storage (fast, no migration)

Extend the existing `useQuestProgress` hook. The hook already tracks `completedQuests` as an array of quest IDs and `completionCount` per quest. Unlock logic can be derived entirely from this existing data:

```typescript
// In a new hook: useQuestUnlocks.ts

function getCurrentSeason(): Season {
  const month = new Date().getMonth(); // 0-indexed
  if (month >= 2 && month <= 4) return "spring";
  if (month >= 5 && month <= 7) return "summer";
  if (month >= 8 && month <= 10) return "fall";
  return "winter";
}

const SEASON_ORDER: Season[] = ["spring", "summer", "fall", "winter"];

const RITES_BY_SEASON: Record<Season, string[]> = {
  spring: ["quest-1", "quest-2", "quest-3"],
  summer: ["quest-4", "quest-5", "quest-6"],
  fall: ["quest-7", "quest-8", "quest-9"],
  winter: ["quest-10", "quest-11", "quest-12"],
};

function useQuestUnlocks() {
  const { isQuestCompleted } = useQuestProgress();

  const fireComplete = isQuestCompleted("quest-0");

  // Which seasons have at least 1 completed Rite?
  const completedSeasons = SEASON_ORDER.filter(season =>
    RITES_BY_SEASON[season].some(qId => isQuestCompleted(qId))
  );

  // First unlocked season = current real-world season
  const startSeason = getCurrentSeason();
  const startIdx = SEASON_ORDER.indexOf(startSeason);

  // Build the unlock chain from the start season
  const unlockedSeasons: Season[] = [];
  if (fireComplete) {
    unlockedSeasons.push(startSeason);
    // Walk forward through rotation, unlocking each season
    // if the previous one has a completed Rite
    for (let i = 1; i < 4; i++) {
      const prevSeason = SEASON_ORDER[(startIdx + i - 1) % 4];
      const nextSeason = SEASON_ORDER[(startIdx + i) % 4];
      if (completedSeasons.includes(prevSeason)) {
        unlockedSeasons.push(nextSeason);
      } else {
        break; // Chain broken, stop unlocking
      }
    }
  }

  const allSeasonsComplete = completedSeasons.length === 4;

  return {
    fireComplete,
    unlockedSeasons,
    completedSeasons,
    allSeasonsComplete,
    // Helpers
    isSeasonUnlocked: (s: Season) => unlockedSeasons.includes(s),
    isQuestUnlocked: (questId: string) => {
      // Fire and Food Foresting always unlocked
      if (questId === "quest-0" || questId === "food-foresting") return true;
      // Fasting unlocked with all seasons
      if (questId === "quest-13") return allSeasonsComplete;
      // Check if quest's season is unlocked
      for (const [season, ids] of Object.entries(RITES_BY_SEASON)) {
        if (ids.includes(questId)) return unlockedSeasons.includes(season as Season);
      }
      // Seasonal Practices and Epics: need all 4 seasons
      return allSeasonsComplete;
    },
    isEpicUnlocked: allSeasonsComplete,
    isSeasonalPracticeUnlocked: allSeasonsComplete,
    seasonProgress: { completed: completedSeasons.length, total: 4 },
  };
}
```

### Option B: Backend (persistent, survives device changes)

Add a `questUnlocks` table or derive from `questCompletions`. Since `questCompletions` already stores `userId + questId + completedAt`, the unlock state can be computed server-side with the same logic. This is a future upgrade if needed. For now, local storage is fine since quest progress already uses it.

**Recommendation: Option A.** The existing `useQuestProgress` hook already stores everything needed. The unlock hook is pure derived state.

## What NOT To Do

- Do NOT change the quest data files (questData.ts, epicQuestsData.ts, seasonalQuestsData.ts). The data stays the same; only the rendering changes.
- Do NOT remove or hide locked quest cards entirely. Players should see what's coming. The greyed-out cards with titles visible build anticipation.
- Do NOT block the forum thread links. If a player navigates directly to a quest's forum URL, let them read it. The lock is on the quest page UI, not on forum access.
- Do NOT modify the `useQuestProgress` hook. The unlock hook reads from it but doesn't change it.
- Do NOT add a backend API for unlocks. Keep this client-side for now.
- Do NOT generate any images. Use existing quest artwork from `/client/public/images/quests/`. If Food Foresting doesn't have a dedicated image, flag it for Rye.
