# Sociocracy and circle-org maps: how the good ones interact, and a spec for ours

Date: 2026-08-16. Research memo, no code changes. Extends `docs/PEERDOM_LESSONS.md` (2026-08-02), which already covers Peerdom's data model, twelve apps, badges (vacant/understaffed striped, representative shading, electable arrow), five circle layouts including the cactus flower, layers, URL-encoded selection, and the ten things we took from it. This memo looks only at how the maps are driven and how they show fill state, and adds nine other products plus D3.

Our baseline (`client/src/pages/VillageMap.tsx`, `shared/mapLayout.ts`): pure deterministic pack (largest child at centre, siblings on one ring), zoom is a viewBox scale around the village centre via +/- buttons, click on circle or seat opens a side panel (bottom sheet on mobile), vacant seats dashed, forming circles at 50% opacity, a concierge search bar, accordion below 768 px. No zoom-into-circle, no breadcrumb, no highlight-on-search, no legend, no keyboard path onto the SVG shapes.

---

## 1. Products and examples

**Peerdom** (`peerdom.com/doc/map/circle-view`, `/doc/map/navigating`, `/releases`, `/doc/peerdom-for-sociocracy`). Nested circles, roles inside, avatars inside roles, "all visible at every zoom level. Nothing collapses or hides." Interaction: pan by drag; zoom by +/- slider, wheel, trackpad pinch, and pinch on mobile (Jul 2023); click any node to open the Inspector (Details + Journal tabs), URL updates on selection so a node is a shareable link; click an avatar to highlight every role that person holds, with a filter badge confirming; hover a peer shows name and focus (Jan 2025); right-click context menu; the map "animates in real time" on data change; deleted nodes briefly enlarge before disappearing (Oct 2024). Fill state: vacant and understaffed roles striped (PEERDOM_LESSONS §2), an empty group is "a dotted, empty circle" (Apr 2024), staffing is a green/orange/red bar in Contribution. Weak: no click-to-zoom into a circle and no breadcrumb anywhere in the docs or release notes I could reach (I could not walk `peerdom.org/sofa` from this tool; PEERDOM_LESSONS walked it and recorded no breadcrumb either); "everything visible" makes a large map a wall of tiny avatars until you pinch; the Inspector is a desktop side panel and mobile is described only as tap-and-drag.

**Holaspirit / Talkspirit** (`help.holaspirit.com/en/article/organize-your-team-with-roles-1c9wnfw/`, `/how-to-use-the-chart-search-1wv902s/`, `/how-can-i-see-my-roles-2mevm2/`, `talkspirit.com/en/structure`). Circle chart where "the size of the circle depends on the role's position in the hierarchy and the number of roles it contains." Interaction: "Click anywhere inside a circle (but not directly on a role) to zoom in and out of your chart"; hover a name and click to slide a detail panel from the side, X to return; type-ahead search over roles, circles and members matching name **or content** (accountabilities, domains), and "the chart will automatically zoom in on it"; filters All / Roles / Circles / Members; seven recent searches kept; radial, tree and list views. Fill state: role cards carry an indicator when "a role is currently hiring or there's a governance proposal requiring your vote"; a separate Vacant and Hiring Roles list. Role page tabs: Purpose, Accountabilities, Domains, Policies, Members, Documents, Activities, Metrics, Checklists, Projects, OKRs. Weak: zoom in and out share one gesture, so mis-taps toggle; the hiring flag is a card badge, never a map glyph; the chart-settings page 301s to talkspirit.com, so current chart options are unverified.

**GlassFrog** (`support.glassfrog.com/*`, `app.glassfrog.com/announcements/154`). Interaction: "Mouse over a circle/role to see the name appear, or to zoom in/zoom out. You'll see the circle selected by the border changing color when you mouse over, and then click to zoom in or out"; deeper labels appear only as you zoom ("zoom in to see labels of sub circles more than three layers deep"); the circle name is a hyperlink to the circle page. Fill state: "Colors show roles that are filled, unfilled, core roles, or roles that do not have an accountability or a purpose"; in v5 unfilled core roles are hidden from the chart and the circle list. Admins export an All Roles Membership List with fillers, focus and unfilled roles. Weak: colour alone carries four meanings; hiding unfilled core roles removes exactly the vacancy a member most needs to see; nothing on mobile.

**Sobol** (`tools.littlefish.foundation/.../sobol`, marketplace listing; `sobol.io` and `support.sobol.io` did not resolve from here, so second-hand). Four views: Circles (default, zoomable), Table, Node (filter teams, roles, assignments, users), Map (geographic, hover shows local time). Fill state unverified. Weak: no first-party doc reachable.

**Maptio** (`blog.maptio.com` initiative-mapping guide, `learning.maptio.com` index, `peerdom.com/blog/peerdom-vs-maptio`, GitHub README). Nested-circle "initiative map": one accountable person ("source") per circle plus helpers, tags that colour-code and filter to "a simplified version with only particular initiatives", a network view of who works with whom, public share URL and embed. Angular + D3. Its own diagnostic: an initiative where "nobody is acknowledged as the natural authority" is a "ghost ship." The learning-hub pages ("Circles and expanded views", "Network map view") render client-side and came back empty, so click-to-zoom and expanded-view mechanics are unverified.

**Kumu** (`docs.kumu.io/guides/focus`, `/guides/layouts`). A network tool with the best-documented focus + context: click-and-hold or select then focus icon "temporarily hiding the rest of the map"; walk out by degree with +/- keys or a digit; direction in/out/all; Esc restores; presets in `@settings` for storytelling. Layouts are fixed, force-directed or scatter; I found no hierarchical circle-pack layout (unverified beyond that page).

**Sociocracy For All / Circle Forward diagrams** (`sociocracyforall.org/organizational-circle-structure-in-sociocracy/`, `/process-roles/`, `forums.sociocracyforall.org/t/.../3406`, `patterns.sociocracy30.org/double-linking.html`). Conventions: circles as tangent or overlapping discs, growth as "a circle turns into 4 circles around one circle, which then turns into a fractal pattern"; the double link is two points shared between adjacent circles, leader (top-down, chosen by parent) and delegate (bottom-up, elected by the sub-circle), "both attend both circle meetings as decision-making members"; each circle carries an aim and a domain. Circle Forward's own site did not surface; the S3 pattern page stands in. Weak: static images, no vacancy notion.

**Nestr** (`nestr.io/help/articles/structure-and-governance-in-nestr`). Circles and roles, a published login-free auto-updating org chart, and "governance lookback": rewind the map to any date. Interaction and fill-state details not in reachable text; unverified.

**Common Sense (holacracy)**: nothing found under that name as a product. Unverified, omitted.

**D3 Zoomable Circle Packing** (`observablehq.com/@d3/zoomable-circle-packing`, `gist.github.com/mbostock/7607535`, `d3js.org/d3-hierarchy/pack`). Click a circle to make it `focus`; click background returns to root; `d3.interpolateZoom(view, [focus.x, focus.y, focus.r*2])` drives the camera; 750 ms, 7500 ms with Alt; labels visible only when `d.parent === focus`, faded during the transition; leaves get `pointer-events: none` so a tap on a leaf hits its parent; hover adds a stroke. `pack` needs `sum` and `sort` first and output depends on input order, so it is deterministic per input. No breadcrumb in the canonical example; breadcrumbs come from Kerry Rodden's sequences-sunburst pattern (D3partitionR reuses it), reading the focus node's ancestor chain.

**Org-chart usability research** (`nngroup.com/articles/suggested-employee-search/`, `/employee-directory-search/`, Creately and Jostle buyer guides). "Finding employees is the most common task done on intranets"; a dedicated find-a-person box on every page; suggested results as you type with photo and contact cut a lookup from 1 min 44 s to about 2 s; users "type in a name, not a word." Buyer guides list the practical questions: who does X, who do I ask, who approves, what is open. Nothing peer-reviewed on nested-circle maps specifically.

## 2. Interaction spec for our map (mobile-first, numbered)

1. **Tap a circle to zoom into it.** Camera animates to `[cx, cy, 2r + margin]` over 400 ms on Bostock's `interpolateZoom` curve. Tap the focused circle's background or the up-crumb to zoom out one level; tap the village ring to reset. A tap on a seat never changes the camera. Focus pushes to history (`?focus=circleId`) so back works and the view is a link.
2. **Breadcrumb bar** above the SVG: Village › Circle › Sub-circle, from the focus node's ancestor chain, each crumb tappable. On mobile it is the only chrome above the map; wheel and pinch also work, the crumb is the primary path.
3. **Focus + context.** Siblings and ancestors of the focus stay drawn at 30% opacity, non-interactive except the parent ring; only children of the focus get labels (Bostock's `parent === focus` rule) so 40 circles stay legible at any level. Never hide the rest entirely (Kumu does; that loses "where am I").
4. **Seat states, five glyphs, colour never alone.** Open call: dashed hollow ring, small "+" glyph. Partial: solid ring, pie-fill of held/needed, "1 of 3" in the tap card, a hairline notch per unfilled seat. Filled: solid, avatar(s) inside. Forming: dotted ring at 50% opacity, hourglass glyph. Expired: solid ring, avatar greyed, clock badge. Colours from one 5-step Okabe-Ito-safe set; the legend lists glyph + word + count ("4 open").
5. **Holders**: up to 3 avatars per seat, then "+n"; hover (desktop) or tap (mobile) opens a small card: role name, circle, holder name and focus string, term end, one action (Raise my hand / Contact / Read seat). References: Peerdom's hover tooltip, Holaspirit's slide panel. Focus moves into the card and back on close, as the current sheet does.
6. **Search = "who does X".** Reuse the concierge bar; add type-ahead over seat names, circle names, aims, accountabilities and holder names; selecting a result zooms the camera to its circle and pulses the seat outline (Holaspirit auto-zoom, NN/g suggested search). Photo and one line per suggestion.
7. **Filters as chips**: Open seats only, My seats, Expiring soon, one circle. A filter dims everything else to 20%; the crumb bar shows the active chip. Tapping an avatar anywhere applies "seats this person holds" (Peerdom's person filter).
8. **Relation lines on demand.** Off by default. A "Links" toggle draws double links as two short arcs between a sub-circle's leader seat and delegate seat and the parent ring (SoFA convention), and `org_relations` (deputy, mentor, successor) as thin dashed chords only for the focused circle. Never draw all lines at once.
9. **Term and season markers.** A seat with `elected_until` within 30 days gets a thin amber arc; expired gets the clock badge (state 4). A season ring around the village shows the current season and next election date. Optional "as of" date picker later (Nestr lookback), reading `health_events`.
10. **Legend** persistent bottom-left on desktop, collapsible on mobile, showing the five glyphs with counts.
11. **Keyboard and a11y.** Every circle and seat is a `<g role="button" tabindex="0">` with an aria-label that already includes state; Enter zooms/opens, Esc zooms out, arrow keys move between siblings, Tab order follows layout order. Announce zoom changes to a live region ("Now inside Land Care, 3 seats, 1 open"). Reduced motion: transitions collapse to 0 ms.
12. **Accordion fallback.** Keep it; switch to it (a) below 480 px, (b) when the smallest seat would render under 24 CSS px at the fitted zoom, or (c) under `prefers-reduced-motion` when the user picks "List". Between 480 and 768 show the SVG with the crumb bar and the accordion beneath, as today.
13. **Performance limits.** Deterministic pack plus SVG is fine to about 60 circles and 400 seats; past that, `<image>` avatars drop frames on mid phones. Above 400 seats draw avatars only for the focus circle's children, initials elsewhere; above 1,000 nodes move to canvas (Bremer's canvas circle-packing gists). Cap quest dots as now.
14. **Print/export.** Export the SVG with legend and crumb as a standalone file plus a PNG via canvas; the print stylesheet hides chrome and prints the current focus level with the accordion below it as text. Public export respects `map.public_structure` (counts, no names).

## 3. Layout engine

Keep the hand-rolled deterministic layout in `shared/mapLayout.ts` and add a zoom camera on top; do not swap in `d3-hierarchy` pack for placement.

Pack's front-chain algorithm is deterministic for a fixed input order, but one new sibling can reflow every other circle, which breaks the "permaculture is at two o'clock" promise the file exists to keep. Our ring pack moves one arc slot and leaves the rest. Pack also sizes by `sum` (leaf value); we size by label and seat count, which is what keeps names readable. What d3 does better is the camera: `d3-interpolate`'s `interpolateZoom` (van Wijk smooth zoom) is a tiny pure function; import that alone, drive it through framer-motion's `useMotionValue`/`animate` on the viewBox string, and keep everything else pure. `d3.packEnclose` is worth importing if we ever need a tight enclosing radius. Force layouts stay banned; nothing above needs one.

## 4. Anti-patterns seen

- Colour as the only state channel (GlassFrog four colours; Peerdom green/orange/red bars).
- Hiding unfilled core roles from the chart (GlassFrog v5) when vacancy is the most-asked question.
- Everything visible at every zoom with no focus rule (Peerdom), so big maps become avatar confetti.
- One gesture for zoom in and out (Holaspirit), causing accidental toggles.
- Vacancy as a card badge or a separate list, never a map glyph (Holaspirit).
- No breadcrumb, so orientation depends on visual memory (Peerdom, D3 canonical example).
- Focus mode that hides the rest of the map completely (Kumu).
- Detail in a right-hand desktop panel with mobile as an afterthought (all of them).
- Client-rendered help pages agents cannot read (Maptio, Sobol); our docs stay static Markdown, as the OKF export already is.
