# Lane L6: Your agent, the harness in every profile

Worktree `wt-r4-agent`, branch `wt/r4-your-agent`, migration `0087`. Code refs are at game-amora `135db66`; line numbers are hints, anchor by content. Dispatch after L5a and L7 land (proposal §8 item 23); if L7 has not landed, ship the RSVP write and leave the intent write behind a flag.

## Objective

Give every member one Profile section, **Your agent**. Outbound: a scoped personal access token so the member's own agent reads what the member already sees and makes exactly two confirmed writes, plus shipped `SKILL.md` files, an OpenAPI slice, setup cards and an optional signed agent-inbox webhook. Inbound: the member stores their own LLM key, encrypted at rest, and the in-app assistant answers on that key and budget. Foundations: an events reader with a zero-token template, an `event_rsvp` draft the member confirms, the "never invent" framing, an about-me note with privacy tiers, and a show/correct control on any sentence the assistant says about a person.

## Design

1. **Data (`0087`).** `agent_tokens` (id, user_id, name, token_hash char(64) unique, prefix, scopes json, created_at, last_used_at, expires_at, revoked_at). `agent_inboxes` (id, user_id unique, url, enabled, consecutive_failures, disabled_reason, last_delivery_at, last_status). `agent_deliveries` (id, inbox_id, kind, payload json, attempts, next_attempt_at, delivered_at, last_error). `member_llm_keys` (user_id, provider enum anthropic|openai_compatible, base_url, ciphertext, iv, tag, last4, set_at). `member_drafts` (id, user_id, kind, payload json, source enum assistant|token, status proposed|confirmed|rejected|expired, decided_at, created_ref). `agent_profiles` (user_id, about_me, about_tier enum private|assistant|members default private, matching_consent bool default 0, corrections json). `assistant_statements` (id, subject_user_id, mode, text, sources json, status active|corrected|withdrawn, correction). Row types live in the lib modules (`DraftRow` pattern); `server/db/schema.ts` is the Phase 1 shadow and tracks no assistant table, so leave it.
2. **Token (`agentTokens.ts`).** `vat_` + 32 random bytes base64url, shown once; sha256 at rest (high entropy, no salt, say why); scopes chosen at mint from `calendar.read`, `directory.read`, `me.read`, `rsvp.write`, `intents.write` (the last only when L7 landed). Mint 5/day, 10 live per user, `expires_at` default 90 days; revoke sets `revoked_at`; every mint, revoke and write is a `recordEvent` row (`actorKind: "agent"`, audience admin). `Bearer vat_...` is honoured on `/api/agent/v1/**` only; anywhere else it is a 401.
3. **Reads are the holder's own routes, never a second permission system** (`villageReaders.ts:27`, `assistantRouter.ts:43`). The block resolves the token, checks scope and a bucket (`agent:${tokenId}` 120/h reads, 20/h writes), mints an in-process session token for the holder with `encodeToken(userId, email, tokenVersion)` (never returned), rewrites `req.url` from a closed map (`/api/agent/v1/calendar` to `/api/events`; `/calendar/:id` to `/api/events/:id`; `/directory` to `/api/org`; `/directory/search?q=` to `/api/messages/people`; `/me` to `/api/me/profile`; `/me/rsvps` to `/api/events` filtered to `myRsvp`) and calls `next()`. Measure first that a rewrite from an unmounted `app.use` before the routers dispatches to the new path in Express 4.21 (hypothesis; if not, call the same library functions with the same arguments and add a parity test per route). The agent never carries `event.manage`, so drafts stay hidden.
4. **Two writes, both confirmed in the contract.** `POST /api/agent/v1/events/:id/rsvp {status, idempotencyKey?}` answers `202 {confirmRequired:true, confirmToken, echo:{eventId,title,startsAt,status,idempotencyKey}, expiresAt}`; the agent sends `{confirm:true, confirmToken, echo}` back; the server checks the echo hash bound into the HMAC token (10 min, signed with the injected `AUTH_TOKEN_SECRET`), then runs the same checks in the same order as `app.post("/api/events/:id/rsvp")` (`events.rsvp_enabled`, `event.rsvp`, `rsvp()` with the idempotency key, `recordEvent`); pass `occurrenceKey` when L5a's `rsvp()` takes it. `POST /api/agent/v1/intents` follows the same shape into L7's create function, behind `AGENT_INTENT_WRITE` until L7 lands. A missing confirm, a mismatched echo, an expired token or a missing scope is a 409 with the reason; nothing writes.
5. **Skills and docs.** `docs/skills/village-calendar/SKILL.md`, `village-directory/SKILL.md`, `village-intents/SKILL.md`: YAML frontmatter `name`, `description`, `version`, `metadata`; a `references/` folder holding the shared `openapi.json` slice for the routes above; both red lines in our voice: "Show the exact write you are about to make and get a yes. Nothing is sent until the member says yes." and "A hidden field is hidden. Never guess it, never fill it from elsewhere; say it is hidden." Serve them read-only at `GET /api/agent/v1/skills`, `/skills/:name/SKILL.md`, `/openapi.json` (public, rate limited). Setup cards for Claude Code, Hermes, OpenClaw and an OpenAI-compatible agent (curl) name the skills URL and the token variable, never a value. Run `node scripts/check-voice.mjs docs/skills` by hand: no gate scans that folder.
6. **Agent inbox (`agentInbox.ts`).** One https URL per member through `guardOutboundUrl`, re-checked at every delivery; per-inbox secret derived as `HMAC(MEMBER_SECRETS_KEY, inboxId)`, shown once, never stored; payload `{id, kind, sentAt, data}` signed over `${sentAt}.${body}`; kinds `test`, `week_ahead` (item 8's template), `weekly_digest` and `opportunity` (L7 through `enqueueAgentDelivery(pool, userId, kind, payload)`). `registerJob("agent-inbox-drain", 5 min)` sends due rows through `guardedFetchJson`, 5 attempts at 1m/5m/30m/2h/12h, then marks dropped; ten consecutive failures disable the inbox and notify the member. Payloads never carry another member's hidden fields.
7. **Member key (`memberSecrets.ts`).** AES-256-GCM under `MEMBER_SECRETS_KEY` (32 bytes hex, new env, one runbook row); absent means the section says "this deployment has no member-secrets key; ask your operator" and refuses to store, never a per-process fallback (`AUTH_TOKEN_SECRET` at `:636` shows why). Routes return `{provider, last4, baseUrl, setAt}` only. `assistant.ts`: `KeySource` gains `member`; `AssistantRequest.memberKey?` wins over village and platform; a member-key call skips the mode's day bucket and the platform cap and pays its own `assistant-member-day:${userId}` 200/day; the per-IP burst guard stays. `assistantProviders.ts` gives the loop one seam: `anthropic` (today's body) and `openai_compatible` (`${baseUrl}/v1/chat/completions`, system as first message, `function` tools, tool results as `role: "tool"`, usage from `prompt_tokens`/`completion_tokens`); adapter tools ship only if the stub loop test passes, else the adapter runs the deterministic, prefetch and no-tools roads and the report says so.
8. **Member mode and the reader.** `POST /api/agent/ask` is the member's in-app assistant: `mode: "member"`, viewer from `capabilityCtx`, `readerCatalog`, `routeQuestion`, then the loop; the concierge tie-break at `/api/assistant/coordinate` resolves the same member key. New reader `events.week` (module `events`, audience member, `maxTokens` 500): the next 7 days through L5a's `listCalendarItems` (or `listGatherings` if absent), `timezone` from the new deps field; renderer "This week: 3 gatherings: Kitchen crew (Tue 18:00), ..." in village time; `assistantRouter.test.ts` forces the PATTERNS and RENDERERS entries. Framing, verbatim in every member-mode prompt: "Names, events and labels about a person come word for word from a tool result or from the member's own note. If it is not there, say: I don't see that anywhere." The reply JSON carries `aboutYou` (a sentence about the asker, or empty) and `draft` (an `event_rsvp` payload `{eventId, status, occurrenceKey?}` validated by `validateDraftPayload`, or empty); a draft lands in `member_drafts` and the member confirms it at `POST /api/agent/drafts/:id/confirm` (calls `rsvp()`); `aboutYou` becomes an `assistant_statements` row.
9. **Panel (`YourAgentPanel.tsx`).** Sections: Bring your agent (tokens, mint with scope checkboxes, one-time reveal, revoke, setup cards, skills links, inbox URL with "send a test"); Run the assistant on your key (provider, key, base URL, last4, remove); About me for my agent (note, tier, consent sentence "The assistant may use this note and my profile to suggest introductions."); What the assistant has said about you (statements with source, Correct, Withdraw); Drafts waiting for your yes. `gameFetch` for every call; copy passes check-voice; `server/lib/**` and `shared/**` are brand hard-clean, so no village name there.
