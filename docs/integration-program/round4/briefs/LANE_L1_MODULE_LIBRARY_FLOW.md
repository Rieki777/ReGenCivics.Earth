## Objective

Move the catalog out of the Admin tab "Modules On/Off" into a public, read-only Module Library at `/modules` with a detail page per module, five grouped shelves, and platform copy for all eighteen modules in `shared/moduleCatalog.ts`. Make the founder flow real on the existing lifecycle enum: Turn on (`off -> preview`) from the detail page, a Go-live card (`preview -> members | public`) at first save, an Admin nav of platform tabs plus Module Library plus one tab per module not off, and per-module readiness. No new state: `module_settings` and the registry only.

R28 ("yes if not mentioned") ratifies ruling items 1 to 5, 25, 26 and the Q1/Q2/Q3/Q5 defaults. R29 (§10.1): rebase cost zero today, housing lands first. ## Design

1. **Registry fields** (`interface ModuleDef`): `group: "coordinate" | "recognise" | "host-and-earn" | "know-and-decide" | "connect"`; `setup: "none" | "optional" | "required"`; `readiness?: () => Promise<{ ready: boolean; hint: string }>` (server-attached like `openStateCheck`). Proposed values, measure against each module's tables: events, forum, feed, messaging, network none; tools, badges, health, map, automation optional; stays, library, exchange, commerce required; core none. `shared/moduleCatalog.test.ts` proves every `MODULES` id has a catalog entry, group and setup, and nothing else does.
2. **Copy** (`shared/moduleCatalog.ts`): `MODULE_GROUPS` (five, ordered, label + gloss) and `MODULE_CATALOG: Record<id, { promise; benefits: string[3..5]; forWhom; setupSummary; dataSummary; hue: number; emblem: string }>`. Platform language, no village brand, no dashes: `check-voice` parses `shared/`, the brand ratchet is 63/63. Ten `docs/modules/*.md` files map to ids by content (badges, events, gratitude-feed = feed, health-dashboard = health, internal-exchange = exchange, material-library = library, messaging, stays, tools-hub = tools, village-map = map); lift from those, write the other eight fresh. `map` stays "Village Map"; L2 may rename one entry later.
3. **Server, S13 block only.** (a) `GET /api/modules/catalog`, public: every module with `id, name, description, core, tier, dataClass, provides, support, pool, group, setup, requires, recommends, legalReview, withdrawn, priceLine`, the catalog entry (rendered server-side like `priceLine`, so the registry stays out of the client bundle) and `imageUrl` from `module_settings.config`. State by the exact `/api/modules` filter: members get `on: boolean` (members or public), admins get `on` and `lifecycle`, anonymous gets no state key. Express matches `app.get("/api/modules")` exactly, so the sub-path is safe; prove it in the test. (b) `GET /api/admin/modules` gains `group, setup, ready | null, examplesAvailable` (seed block in `server/seeds/examples-seed.json`, not seeded, not retired) and `maxLifecycle` = lowest `effectiveLifecycle` among `requires` (core = public). (c) `PUT .../lifecycle` accepts optional `examples: false`: absent keeps today's seed-on-enable, false skips `seedExamples` for that request only. (d) `PUT /api/admin/modules/:id/image { imageUrl | null }`: refuse anything not starting `/api/uploads/` (the forum's rule); merge `{...defaultConfig, ...existing, imageUrl}` exactly as `stampListing` does, because one key written into an empty config silently drops `defaultConfig` at six read sites; write through `setModuleConfig` so validators and `module_events` fire.
4. **Readiness** (`server/lib/modules.ts`): `attachModuleReadiness(getPool)` sets `readiness` on every `setup !== "none"` module; default reader `hasRealContent(pool, id)` (real rows only) with a per-module hint ("Post one room and a price first"); stays additionally needs an `accommodation_prices` row (hypothesis). Call it once, idempotently, immediately before `app.get("/api/admin/modules"`: route registration runs at boot, so it is attached at boot without touching the boot block. `setModuleLifecycle` refuses `next` above `maxLifecycle` with 409 naming the dependency (§8 item 11); lowering a dependency stays as today. Existing e2e cases set forum public before feed public (measured); run the whole file.
5. **`/modules`** (lazy, ungated, nav entry under Guides): five shelves; card = art, name, promise, tier pill (included silent), pool badge (`POOL_REASON_COPY` wording), "On in this village" for signed-in viewers, "Always on" for core, "Preview" for admins only; last card "Build one, get paid in $ReGen" linking the upstream repo's `docs/modules/BUILDING_A_MODULE.md` (base of `BUILDER_GUIDE_URL`) and `https://regencivics.earth/builders-pool` (hub route measured). Art: village `imageUrl`, else `/images/modules/<id>.webp` (L1a), `onError` to `ModuleArt` (gradient from `hue`, lucide emblem, zero image budget). Withdrawn renders with its line, never hidden.
6. **`/modules/:id`**: hero art, promise, benefits, who it is for, what you will set up (`setup`, `setupSummary`, `vendor.setupSteps`), what data it holds, works well with (`recommends` as names), support, price, pool line. Admins (`useAuth().user.role` admin or founder; bearer `authToken()`, the same token `AdminGate` uses) see lifecycle plus one button **Turn on** (`off -> preview`; legal-card modules keep the exact `window.confirm` text from `ModulesTab.setLifecycle`) with "Start with example content" when `examplesAvailable`; for `setup === "none"` the Go-live card appears right after; an image field uses `prepareImageForUpload`, `POST /api/admin/brand/image`, then the image PUT. Members and anonymous see no buttons.
7. **Go-live card**: shown when `preview` and (`setup === "none"` or `ready.ready`); Members only / Everyone / Not yet; default Members for `member-pii`, Everyone for `village-content`; Everyone greyed with the reason when `maxLifecycle` is below public; names examples showing ("3 examples showing; replace or remove them before going live"). In Admin it mounts once in `<main>` above the panel, keyed by `TAB_MODULE[activeTab]`, re-reading `/api/admin/modules` on `visibilitychange`, on a `module:saved` window event, and every 20 s while a preview module's tab is open: first save is detected by readiness flipping, so no tab's save handler is edited. Legal cards stay at enable, unchanged.
8. **Admin nav**: `TAB_MODULE` maps `circles-map -> map`, `events-admin -> events`, `tools-admin -> tools`, `stays-admin -> stays`, `exchange-admin -> exchange`, `badges-admin -> badges`, `library-admin -> library`, `health-admin -> health`, `calls-admin -> automation`, `products -> commerce`, `forum-moderation -> forum`; everything else is platform. Hypothesis: the ruling maps Org Chart and Season Shapes to `map`, but `/api/org` and `/api/admin/seasons/patterns` sit behind no `requireModule` and `OrgChartTab` has no off branch; if they work with map off, keep them platform and report it. `filterNavByModules(groups, lifecycles)` drops a mapped tab whose module is off, else adds `badge: preview | members | everyone`, one span in `AdminNav`. Key `modules` stays (deep links survive), label "Module Library"; `ModulesTab` renders the shelf grouped by `group` with its existing controls, each card linking to `/modules/:id`. `Admin()` fetches `/api/admin/modules` once per token; while unloaded, filter nothing.
