### MED-1 · Bootstrap reports the founder's link was emailed when no email provider exists

- **Surface:** LOCAL, fresh fork. Route `POST /api/admin/bootstrap`.
- **Repro:** on a deployment with no Resend key (the state every fork boots in), post
  `{"password":"...","email":"...","name":"..."}` to `/api/admin/bootstrap`.
- **What happens:** the response is `{"success":true,"userId":"...","emailed":true,"claimUrl":"..."}`
  and the server log on the same request reads `[RESEND] API key not set, skipping email`.
  Nothing was sent. The `claimUrl` is returned beside it, so an operator running the runbook curl
  recovers; an operator who reads `emailed: true` and closes the terminal has stranded the only
  account that can do anything.
- **Persona line:** "It told me the founder's link was emailed. I waited two days for it."

### MED-2 · The runbook's own module step refuses to run on trunk

- **Surface:** LOCAL, `b5bed01`. `docs/FORK_RUNBOOK.md:330` instructs a fork to run
  `node scripts/enable-all-modules.mjs --base ... --email ... --password ...`.
- **Repro:** run it, with or without `--dry`.
- **What happens:** *"This script does not know about 5 module(s) the server offers: resources,

  know which modules I now have."
